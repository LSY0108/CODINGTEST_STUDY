# 1. [전화번호 목록] 문제 접근 방법 정리
## 문제 파악
전화번호 목록 `phone_book`이 주어진다. <br>
목록에 있는 전화번호 중 어떤 번호가 다른 번호의 접두사(prefix) 인 경우 `false`를 반환하고, <br>
그렇지 않으면 `true`를 반환한다.

예시
- `["119", "97674223", "1195524421"]` → `false`
- `["123", "456", "789"]` → `true`

## 접근 방법
1. `phone_book`을 문자열 기준으로 **정렬**한다.

2. 정렬된 배열에서 인접한 두 번호만 **비교**한다.

3. 앞 번호가 뒤 번호의 접두사라면 즉시 `false`를 반환한다.

4. 모든 비교를 통과하면 `true`를 반환한다.

# 2. [완주하지 못한 선수] 문제 접근 방법 정리

## 문제 파악
마라톤에 참가한 선수들의 이름이 담긴 배열 `participant`와  
완주한 선수들의 이름이 담긴 배열 `completion`이 주어진다.

단 한 명의 선수를 제외하고는 모든 선수가 완주했을 때,  
**완주하지 못한 선수의 이름을 반환**한다.

- `completion`의 길이는 `participant`보다 1 작다.
- 참가자 중 **동명이인**이 있을 수 있다.

### 예시
- `["leo", "kiki", "eden"]`, `["eden", "kiki"]` → `"leo"`
- `["mislav", "stanko", "mislav", "ana"]`, `["stanko", "ana", "mislav"]` → `"mislav"`

---

## 접근 방법 (HashMap 사용)

동명이인이 있을 수 있으므로,  
**선수 이름을 key, 등장 횟수를 value로 하는 HashMap**을 사용해 해결한다.

1. `HashMap<String, Integer>`를 생성한다.
2. `participant` 배열을 순회하며 각 선수 이름의 등장 횟수를 `+1` 한다.
   - 처음 등장하는 이름은 `getOrDefault(name, 0)`을 사용해 0부터 시작한다.
3. `completion` 배열을 순회하며 완주한 선수의 등장 횟수를 `-1` 한다.
4. HashMap을 순회하며 값이 `0`이 아닌 이름을 찾는다.
   - 해당 이름이 **완주하지 못한 선수**이다.

---

- 참가한 선수 → `+1`
- 완주한 선수 → `-1`
- 최종적으로 값이 `0`이 아닌 선수 = 완주하지 못한 선수
