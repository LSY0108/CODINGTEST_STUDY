# 1. [소수 만들기] 문제 접근 방법 정리
## 문제 파악
주어진 배열 `nums`에서 서로 다른 3개의 수를 선택하여
그 합이 **소수**가 되는 경우의 개수를 구하는 문제이다. 

## 접근 방법
우선 이 문제는 입력 크기가 크지 않다. 
`nums`의 길이는 최대 50이므로, 서로 다른 3개의 수를 고르는 모든 경우의 수는 
`50C3`으로 약 2만 개이다.

코딩 테스트에서 완전 탐색이 가능한지를 판단할 때는 
**전체 반복 횟수 규모**를 먼저 본다.
일반적으로 반복 횟수가 **수백만 단위**라면 시간 제한 내에서 충분히 처리할 수 있다.

따라서 모든 경우를 직접 확인하는 **완전 탐색 방식**으로도
시간 제한에 여유가 있다고 판단했다. 

구현은 3중 반복문을 이용해 서로 다른 인덱스 `i < j < k`를 만족하는 
모든 조합을 만들고, 각 조합에 대해 세 수의 합을 구한 뒤
해당 합이 소수인지 판별하여 소수인 경우에만 카운트를 증가시키는 방식으로 문제를 해결했다. 

<br>

**🚦 완전 탐색 반복 횟수 기준**
> 완전 탐색 적용 가능 여부를 판단할 때 참고한 기준은 다음과 같다.

| 반복 횟수   | 판단    | 비고           |
| ------- | ----- | ------------ |
| 1천 ~ 1만 | 매우 안전 | 부담 없이 사용 가능  |
| 10만     | 여유    | 완전 탐색 적합     |
| 100만    | 가능    | 대부분 문제에서 OK  |
| 1천만     | 애매    | 연산 내용에 따라 다름 |
| 1억 이상   | 위험    | 다른 방법 고려 필요  |
